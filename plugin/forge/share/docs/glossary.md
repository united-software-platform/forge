# Глоссарий модели forge

Понятия, которыми пользуются нормы модели `MDL-NNN`, навыки плагина forge и имена компонентов
его ядра. Документ — данные поставки: в проекте-потребителе он выдаётся вместе с нормами вызовом
`forge norms`.

## Структура модели

| Понятие | Определение |
|---------|-------------|
| Модель (Model) | Описание структуры графа требований в файлах каталога `model/<пакет>.v<MAJOR>/`; единственный источник истины о структуре |
| Манифест (Manifest) | Файл `_manifest.yaml` модели: имя модели, версия, перечисления |
| Тип узла (Node Type) | Вид узлов графа с кодом, номером, русским и английским именами и полями; описывается отдельным файлом в `types/` |
| Код типа (Type Code) | Неизменная аббревиатура типа узла из заглавных латинских букв; префикс кода экземпляра |
| Код экземпляра (Instance Code) | Идентификатор узла вида `<КОД ТИПА>-NNN` |
| Поле (Field) | Атрибут типа узла с номером, именем, типом и обязательностью; идентичность поля — его номер |
| Перечисление (Enum) | Именованный набор значений с номерами, на который ссылается поле типа `enum.<имя>` |
| Значение перечисления (Enum Value) | Элемент перечисления: номер неизменен, имя — заглавные латинские буквы с подчёркиваниями |
| Сигнатура связи (Relation Signature) | Описание допустимой связи между узлами: номер, имя, домен `from`, кодомен `to`, кардинальности, ацикличность |
| Кардинальность (Cardinality) | Границы `min`/`max` числа связей у узла на одной стороне сигнатуры |
| Ацикличность (Acyclicity) | Требование отсутствия циклов по связи; по умолчанию истинно |
| Занятые номера (Taken Numbers) | Перечень номеров и имён полей, номеров и имён значений перечислений и кодов экземпляров, выданных однажды и не выдаваемых повторно; ведётся инструментом |
| Место (Place) | Файл модели от её каталога и строка в нём; место называет каждое нарушение |
| Нарушение (Finding) | Несоответствие модели нормам формата или структуры: место, элемент модели и что с ним не так; проверка называет все нарушения за один прогон |
| Чтение модели (Model Reading) | Объекты модели, построенные из её файлов, вместе с нарушениями формата; модели нет, если не прочитан манифест |

## Версия и дескриптор

| Понятие | Определение |
|---------|-------------|
| Версия (Version) | Номер модели вида `X.Y.Z` из манифеста; версии сравниваются по старшинству разрядов |
| Разряды версии (Version Components) | Три части версии `X.Y.Z`: MAJOR — ломающее изменение контракта, MINOR — структура, PATCH — описания |
| Дескриптор (Descriptor) | Скомпилированное представление модели одной версии в JSON; дескриптор выпущенной версии лежит в `model/releases/` |
| Хеш дескриптора (Descriptor Hash) | Контрольная сумма `sha256` структурных элементов дескриптора; описания в неё не входят |
| Компиляция модели (Compilation) | Итог сборки модели: дескриптор, если нарушений нет, иначе перечень всех нарушений формата и структуры; выполняется каждой подкомандой, читающей модель |

## Изменение и выпуск

| Понятие | Определение |
|---------|-------------|
| Дельта (Delta) | Перечень операций, переводящих последнюю выпущенную версию модели в рабочую; печатается `forge diff` |
| Операция (Operation) | Одна операция дельты: элемент модели, класс операции и пояснение |
| Классы операций (Operation Classes) | Разбиение операций дельты на безопасные, ломающие контракт и разрушающие данные; класс определяет предупреждение при выпуске |
| Безопасная операция (Safe Operation) | Операция, после которой потребители версии и данные остаются корректными |
| Ломающая операция (Breaking Operation) | Операция, нарушающая ожидания потребителей прежней версии контракта |
| Разрушающая операция (Destructive Operation) | Операция, удаляющая данные хранилища |
| Гейт совместимости (Compatibility Gate) | Проверка выпуска, останавливающая его на ошибках процесса: версия не повышена, версия понижена, номер выдан повторно |
| Решение гейта (Gate Decision) | Исход гейта совместимости: выпускать, выпускать нечего или отвергнуто; отвергнутое решение называет нарушения, решение «выпускать» несёт дельту |
| Выпуск (Release) | Агрегат записанных файлов версии модели: миграции в порядке применения, дескриптор с пополненным перечнем занятых номеров, запись реестра и добавленные занятые номера; записывается целиком `forge gen` |
| Свёртка (Baseline) | Миграция, создающая схему модели целиком без истории; выпускается `forge gen --baseline` |
| Шаг миграции (Migration Step) | Нейтральная операция над схемой, выведенная из операции дельты: что изменить, без диалекта СУБД и имени файла |

## Хранилище

| Понятие | Определение |
|---------|-------------|
| Миграция (Migration) | Неизменяемый файл SQL каталога `changelog/`, переводящий схему хранилища на шаг версии |
| Замыкающая миграция (Closing Migration) | Последняя миграция версии: записывает версию и хеш модели при условии, что в хранилище лежит хеш предыдущей версии |
| Отпечаток версии (Version Stamp) | Версия и хеш модели, записанные в хранилище замыкающей миграцией |
| Реестр выпусков (Release Registry) | Файл `changelog/registry.yaml` с перечнем выпущенных версий, файлов и их контрольных сумм |
| Запись реестра (Registry Entry) | Строка реестра выпусков: версия, хеш модели и контрольные суммы выпущенных файлов |
| Запросы целостности (Integrity Checks) | Запросы SQL, проверяющие то, что схема не выражает: кардинальность и ацикличность; печатаются `forge checks` |
| Правило целостности (Integrity Rule) | То, что проверяется запросом целостности, а не схемой: граница кардинальности стороны связи, ацикличность связи, подтверждённость связи против текущей ревизии цели |
| Нарушение целостности (Integrity Violation) | Правило целостности и узлы или связи, которые его нарушают; называется `forge verify` |
| Расхождение схемы (Schema Drift) | Несовпадение схемы хранилища с моделью: таблица, колонка или отпечаток версии; называется `forge verify` |

## Цикл намерения

| Понятие | Определение |
|---------|-------------|
| Стадия (Stage) | Шаг замкнутого цикла намерения: намерение, валидация, реализация модели, преобразование в миграцию, накат, сверка с фактом |
| Исход стадии (Stage Outcome) | Результат стадии из закрытого перечня: пройдено, отклонено, остановлено, ошибка |
| Вердикт (Verdict) | Оценка одной позиции намерения стадией сверки: исполнено или не исполнено |
| Состояние намерения (Intent State) | Положение намерения в цикле: Черновик, Валидировано, Реализовано, Выпущено, Применено, Подтверждено, Доработка, Прервано; меняется только разрешённым переходом |
| Отчёт итерации (Iteration Report) | Машиночитаемый итог одной итерации цикла: намерение, номер итерации, состояние, исходы стадий, вердикты и причина завершения |
| Сценарий прогона (Run Scenario) | Файл, задающий вход цикла — код намерения и позиции — и исходы стадий по итерациям для подставных шагов |
