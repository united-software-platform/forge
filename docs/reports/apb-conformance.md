# Приёмочный отчёт соответствия forge образцу плагина агента

Отчёт сверяет forge после changes `package-forge-as-plugin` и `layer-forge-core` с образцом плагина агента
(Agent Plugin Blueprint, APB) по [чек-листу соответствия](../spec/agent-plugin-blueprint/conformance.md).
Точка отсчёта — [базовый отчёт](./apb-conformance-baseline.md); форма и нумерация проверок те же.

## Применимость и утверждённые отклонения

Оси применимости не изменились: «Среда исполнения» и «Модель работы» по-прежнему не совпадают,
отклонение утверждено владельцем — см. [базовый отчёт](./apb-conformance-baseline.md#применимость-образца).
Исходы «Неприменимо» проверок 36, 37, 40–45, 47–51 держатся на этом решении.

Отклонения, утверждённые владельцем и воплощённые в change:

| Отклонение | Требование APB | Что сделано вместо |
|------------|----------------|--------------------|
| Зависимости ядра | APB-003 (1) — ноль зависимостей | `pyyaml==6.0.3`, `psycopg[binary]==3.3.5` в `plugin/forge/src/requirements.txt`; те же пины в `pyproject.toml`, сверку выполняет тест |
| Способ окружения | эталон — вариант `venv-target` | `uv venv` + `uv pip install`, затем `python3 -m venv` + `pip install`: `psycopg[binary]` ставит бинарные колёса, установка через `--target` без изоляции интерпретатора ненадёжна |
| Стек тестов | эталон — `unittest` без зависимостей | pytest; прогон одной командой `uv run --extra dev pytest -q`, окружение `uv` ставит сам |
| Сеть | среда без сети | `forge verify` подключается к хранилищу по DSN; первый вызов входа требует сети для сборки окружения |
| `CLAUDE.md` и `AGENTS.md` | — | `@`-импорт норм из `plugin/forge/share/` — локальное отличие от файлов kit'а из `.sdd-kit-manifest.json`; переустановка kit'а покажет расхождение хеша и затрёт строки |

## Расхождения норм модели с ядром

При нумерации норм смысл положений не менялся. Расхождения положений с поведением ядра
записаны здесь, а не исправлены молча; при раскладке ядра по слоям правила перенесены как есть,
вместе с расхождениями:

| № | Нормы | Норма | Ядро |
|---|-------|-------|------|
| Р1 | `MDL-018`, `MDL-025`, `MDL-026` | Выпуск останавливают три случая; PATCH — правка описаний без миграции | Четвёртая остановка: версия повышена при неизменной структуре — исход «отвергнуто» с нарушением «выпускать нечего», код `1` (`contract/domain.py`, `CompatibilityGate.decide`). Подъём PATCH после правки только описаний остановлен гейтом |
| Р2 | `MDL-022`, `MDL-023` | «Удаление элемента» — в ломающих, удаление поля, типа, связи — в разрушающих | Удаление поля, типа узла, связи — разрушающие; удаление перечисления и значения перечисления — ломающие (`contract/domain.py`, `diff`) |
| Р3 | `MDL-021` | Перечень безопасных операций | Безопасными считаются и не названные в норме операции: добавление перечисления, переименование значения перечисления и связи, расширение домена и кодомена (`contract/domain.py`, `diff`) |
| Р4 | `MDL-016`, `MDL-025` | Повторная выдача кода экземпляра останавливает выпуск | `taken.codes` читается, но ни валидацией, ни гейтом не сверяется; гейт проверяет только номера полей (`contract/domain.py`, `_reused`) |
| Р5 | `MDL-001`, `MDL-017` | Раскладка называет манифест, `types/`, `relations.yaml`; пример — раздел `taken:` | Инструмент пишет занятые номера в `_taken.yaml` каталога модели (`release/infrastructure/files.py`, `FileReleaseRepository`); раскладка этот файл не называет |
| Р6 | `MDL-005`, `MDL-010` | Имена — буквы и подчёркивания | Допускаются и цифры: `ENUM_VALUE_RE`, `NAME_RE` (`contract/domain.py`) |

Решение по каждому расхождению — что верно, норма или ядро, — принимает владелец; исправление
выпускается отдельной правкой нормы с подъёмом версии `model-rules.md` либо правкой ядра.

## Ограничения отчёта

- **Проверка 2 — маркетплейс источника `directory`.** Claude Code читает такой плагин на месте,
  из `plugin/forge/` репозитория; установка из GitHub-маркетплейса с копированием в кеш
  не проверялась.
- **Замечание к kit'у: два неиспользуемых `noqa` в `tools/host-runner/runner.py`.** Ruff называет их
  правилом `RUF100`. Файл принадлежит kit'у и записан в `.sdd-kit-manifest.json` с хешем, поэтому
  в репозитории не правится: находка подавлена исключением `RUF100` для этого файла
  в `pyproject.toml`. Пометки убираются в самом kit'е, после чего исключение снимается.
