# Базовый отчёт соответствия forge образцу плагина агента

Отчёт сверяет текущее состояние forge с образцом плагина агента (Agent Plugin Blueprint, APB)
по [чек-листу соответствия](../spec/agent-plugin-blueprint/conformance.md) до начала миграции.
Отчёт — основание change `package-forge-as-plugin`; по ходу проверки ничего не исправлялось.

## Применимость образца

Шаг 1 чек-листа требует совпадения четырёх осей классификации APB. Совпадают не все:

| Ось | APB | forge | Совпадение |
|-----|-----|-------|------------|
| Тип | Инструмент разработки: плагин агента с входом командной строки | Инструмент разработки с входом командной строки, плагином не является | Да — после миграции |
| Исполнитель | LLM-агент в сеансе Claude Code | Человек, CI; после миграции — агент через навыки | Частично |
| Среда исполнения | Локальный процесс без сети | Локальный процесс; `verify` подключается к PostgreSQL по DSN | Нет |
| Модель работы | Порождение артефактов по шаблону и проверка прогоном | Компиляция модели в дескриптор и миграции, гейт совместимости, цикл намерения | Нет |

> **Важно:** несовпадение названо владельцу, и владелец утвердил осознанное отклонение: forge
> перенимает техническое решение APB — поставку плагином, единый вход, слои, навыки, нормы
> в поставке, — но не модель работы. Конвейер артефакта и приёмка шаблона
> ([APB-009](../spec/agent-plugin-blueprint/decisions.md#apb-009-конвейер-артефакта),
> [APB-010](../spec/agent-plugin-blueprint/decisions.md#apb-010-приёмка-шаблона-перебором))
> к forge неприменимы; адресацию артефактов forge задают его собственные нормы модели.

Отличия по прочим осям, утверждённые владельцем:

- **Зависимости:** `pyyaml` и `psycopg` сохраняются с пинами `==`; окружение собирается
  в `${CLAUDE_PLUGIN_DATA}`.
- **Взаимодействие:** `verify` выполняет сетевое обращение к хранилищу.
- **Стек тестов:** pytest вместо `unittest` — воплощение, а не требование APB.

## Сверка правил проекта

Спецификация ссылается на коды `CLAR`, `CQRS`, `DDD`, `DOC`, `TERM`, `DOCK`, `GIT`, `MAKE`.
Все коды существуют в `rules/` проекта и означают то же; все 40 ссылок
`../../../rules/…#якорь` разрешаются в действующие заголовки. Расхождений правил нет.

Коды `BKL-NNN` и требования OpenSpec эталона относятся к плагину `backlog` и упомянуты
спецификацией текстом — к правилам проекта они не относятся.

## Порядок исправления

1. **APB-001** — корень `plugin/forge/`, `plugin.json`, `marketplace.json`, `.claude/settings.json`.
2. **APB-002** — вход `bin/forge`, корень поставки от пути входа, корень проекта
   от `CLAUDE_PROJECT_DIR`, коды возврата.
3. **APB-003** — `requirements.txt` с пинами `==`, окружение в `${CLAUDE_PLUGIN_DATA}`.
4. **APB-007** — нормы `MDL-NNN` и глоссарий в `share/`, подкоманды `norms` и `sample`,
   `@`-импорт в `CLAUDE.md`.
5. **APB-008** — навыки `forge:model-change` и `forge:model-release`.
6. **APB-011, APB-012** — переменные каталогов, рекомендация `.gitignore`, тесты одной командой,
   `openspec validate --strict`.
7. **APB-004..006** — слои ядра: отдельный change `layer-forge-core`.

## Ограничения отчёта

- Проверки 8, 54, 58 выполнены частично чтением: прогон всех веток кода невозможен без тестового
  окружения.
- Проверки 28, 29, 55 не выполнены: в репозитории нет рабочей модели, а в окружении — `pytest`.
- Отклонение по осям применимости утверждено владельцем в обсуждении миграции; его пересмотр
  меняет исходы проверок 36, 37, 40–45, 47–51.
