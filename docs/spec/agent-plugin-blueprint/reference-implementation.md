# Эталонная реализация

Как образец APB воплощён в плагине `backlog` проекта `formular`: соответствие ролей образца
понятиям и путям эталона и предмет, который за эталоном стоит. Пути эталона даны текстом:
в целевом проекте их нет.

## Что целевой проект заменяет

Образец переносится, предмет — нет. Целевой проект вносит своё:

| Что | Чем заменяется |
|-----|----------------|
| Имя плагина, входа, навыков | Имена своего предмета |
| Нормы `BKL-NNN` и глоссарий | Нормы своего предмета с собственным префиксом, не совпадающим с префиксами правил проекта ([TERM-007](../../../rules/terminology.md#каноническое-имя-и-аббревиатура)) |
| Агрегат «беклог», адрес «операция и предмет» | Агрегат своего порождённого артефакта и его адрес |
| Грамматика задач: отметка, `Проверка:`, `Выполнено ранее:`, `Стоп-знак` | Грамматика своего артефакта, если она иная; правила структуры — в домене |
| Каркас: коды `BKL-005`..`BKL-008`, первые две задачи | Свой каркас, если артефакт исполняется агентом |
| Шаблоны операций | Свои шаблоны в своём каталоге шаблонов |

Сохраняется без изменений: поставка плагином, вход с самонахождением корня и кодами `0`/`1`/`2`,
ядро без зависимостей, три слоя и разделение контрактов, нормы как данные поставки, разделение
ролей входа и навыков, проверка до записи, приёмка шаблона перебором, адресация от корня проекта,
проверка прогоном.

## След предмета

Образец не принадлежит предметной области, но эталон применялся к конкретной: это видно
по шаблонам операций самого репозитория-источника в `templates/`:

| Шаблон | Что за ним стоит |
|--------|------------------|
| `bootstrap.md` | Подъём нового проекта: фасеты, удалённый репозиторий, лицензия, публикация |
| `create-project.md` | Первичное размещение проекта |
| `move-project.md`, `rename-project.md`, `extract-project.md` | Перемещение, переименование и извлечение проекта |
| `compose-group.md` | Приведение состава группы проектов |
| `restructure-layout.md`, `revert-layout.md` | Реструктуризация раскладки по шаблону и возврат к состоянию до версии |

Предмет — управление проектами рабочего пространства: операции с необратимыми шагами —
публикацией, переименованием с внешними ссылками, переносом, — где нужен порядок, след
и подтверждение владельца. Требований образца этот предмет не порождает: он объясняет,
почему в образце есть стоп-знак и признак исполнения.
