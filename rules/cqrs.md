## Таблица правил

| ID | Правило |
|----|---------|
| CQRS-001 | Контракт записи объявляется в домене и содержит только изменяющие операции |
| CQRS-002 | Контракт записи не содержит операций чтения |
| CQRS-003 | Контракт чтения объявляется в слое приложения и возвращает только модели чтения |
| CQRS-004 | Контракт чтения не содержит изменяющих операций |
| CQRS-005 | Сценарий-запрос зависит только от контракта чтения |
| CQRS-006 | Реализации контрактов чтения и записи — отдельные компоненты слоя инфраструктуры |

## Принцип

Операции чтения и записи разделены на уровне контрактов репозитория. Один агрегат — два контракта:

| Контракт | Слой | Назначение |
|----------|------|------------|
| `OrderWriteRepositoryInterface` | домен | Работает с доменной моделью: создать, изменить, удалить; чтения не содержит |
| `OrderReadRepositoryInterface` | приложение | Возвращает модели чтения, собранные под конкретный экран или ответ |

Разделение окупается тем, что у чтения и записи разные требования. Записи нужна целостность
агрегата: загрузить целиком, проверить инварианты, сохранить целиком. Чтению нужна форма ответа:
поля из нескольких агрегатов, посчитанные величины, порядок и постраничность. Один контракт,
обслуживающий обе задачи, неизбежно уступает в одной из них.

## Подробное описание

- **[CQRS-001]** **Контракт записи** объявляется в **домене**. Его операции принимают и возвращают
  доменные объекты. Он содержит только изменение состояния и выдачу идентификаторов.
- **[CQRS-002]** Контракт записи **не содержит операций чтения** — ни выборки по условию,
  ни загрузки по идентификатору. Если сценарию-команде нужны данные агрегата, он получает их
  через контракт чтения.
- **[CQRS-003]** **Контракт чтения** объявляется в **слое приложения**: его реализация обращается
  к инфраструктуре, а домен таких контрактов не объявляет
  ([CLAR-006](./clean-architecture.md#слой-домена-clar-002004-clar-006)). Операции возвращают модели
  чтения — структуры под конкретный ответ, а не доменные объекты.
- **[CQRS-004]** Контракт чтения не содержит изменяющих операций.
- **[CQRS-005]** **Сценарий-запрос** зависит только от контракта чтения. Сценарий-команда —
  только от контракта записи.
- **[CQRS-006]** Реализации двух контрактов — **отдельные компоненты** слоя инфраструктуры.
  Общая реализация на два контракта сводит разделение к формальности.

## Принадлежность контрактов слоям

Правило задаёт принадлежность компонента слою, а не его расположение в дереве проекта. Как слой
воплощён физически — каталогом, пакетом, модулем или пространством имён — определяет проект.

| Компонент | Слой | Чем определяется принадлежность |
|-----------|------|--------------------------------|
| Контракт записи | домен | Оперирует доменной моделью и выполним в терминах домена |
| Контракт чтения | приложение | Его реализация обязана обратиться к хранилищу |
| Модель чтения | приложение | Форма ответа, а не доменное понятие |
| Реализация контракта записи | инфраструктура | Знает о механизме хранения |
| Реализация контракта чтения | инфраструктура | Знает о механизме хранения |
| Сценарий-команда | приложение | Зависит от контракта записи |
| Сценарий-запрос | приложение | Зависит от контракта чтения |

## Пример

```text
// ДОМЕН — контракт записи: только изменения [CQRS-001, CQRS-002]
Contract OrderWriteRepositoryInterface:
    create(order: Order): void
    update(order: Order): void
    delete(id: OrderId): void

// Запрещено в контракте записи — любая операция чтения [CQRS-002]
    findById(id: OrderId): Order
    findByCustomerAndPeriod(customerId, from, to): list of Order

// ПРИЛОЖЕНИЕ — контракт чтения: только выборки [CQRS-003, CQRS-004]
Contract OrderReadRepositoryInterface:
    findById(id: string): OrderDetailView
    listByCustomerId(customerId: string): list of OrderSummaryView

// ПРИЛОЖЕНИЕ — модель чтения: форма ответа, не доменный объект
View OrderSummaryView:
    id: string
    customerName: string        // поле соседнего агрегата — для чтения это допустимо
    totalAmount: int
    status: string

// ПРИЛОЖЕНИЕ — сценарий-команда зависит от контракта записи [CQRS-005]
UseCase UpdateOrderUseCase implements UpdateOrderUseCaseInterface:
    constructor(orders: OrderWriteRepositoryInterface)

// ПРИЛОЖЕНИЕ — сценарий-запрос зависит от контракта чтения [CQRS-005]
UseCase GetOrderUseCase implements GetOrderUseCaseInterface:
    constructor(orders: OrderReadRepositoryInterface)

// ИНФРАСТРУКТУРА — две отдельные реализации [CQRS-006]
Implementation StoredOrderWriteRepository implements OrderWriteRepositoryInterface:
    create(order: Order): void      // отображает доменную модель на схему хранения
    update(order: Order): void
    delete(id: OrderId): void
    findById(id: OrderId): Order

Implementation StoredOrderReadRepository implements OrderReadRepositoryInterface:
    findById(id: string): OrderDetailView            // собирает модель чтения напрямую
    listByCustomerId(customerId: string): list of OrderSummaryView
```
